# {{BOT_ID}}

A nostrherd bot. People reach it in a Nostr group chat by starting a
message with `{{BOT_ID}}:`. Its answers are stamped with its name by the
host and published under the operator's account.

Generated by `nostrherd init`.

## The files

- `AGENTS.md` is yours. It holds who this bot is and what it will do.
  The host never edits it, and it is the only file you need to write.
- `CLAUDE.md` points at `AGENTS.md` so the same corpus works whichever
  agent CLI runs it.
- `startup.md` is host-managed between its markers. Do not edit inside
  them. Do not copy protocol facts out of it into `AGENTS.md`: the host
  rewrites its own blocks, and a hand-made copy will go stale.
- `.nostrherd/` holds generated chat history and checkpoints. It is
  gitignored and belongs out of the repository.

Every channel this bot answers in shares this one directory.

## Registration

`nostrherd init` registers this corpus automatically. Its output names the
registry it updated; by default that is `~/.config/nostrherd/bots.toml`
(or `$XDG_CONFIG_HOME/nostrherd/bots.toml`). `--config` selects another file.
Only `--print-only` leaves registration to you: add its stdout entry to
the registry before starting the host.

The entry identifies this corpus as:

```toml
[[bots]]
id = "{{BOT_ID}}"
corpus = "{{CORPUS_PATH}}"
kind = "{{KIND}}"
```

## Check it works

Describe the bot in `AGENTS.md`. Keep Herdr and `kelpied` running, and supply
`NOSTRHERD_PRIVATE_KEY` and `NOSTRHERD_RELAY_URL` to the host through your
secret manager. There is no command-line key flag.

Run `nostrherd --check` to check the registry and database, then `nostrherd`
to start the host. If you used a custom registry, pass `--config` with that
same path to both commands.

From the operator's account, say `{{BOT_ID}}: hello` in a channel it can post in,
and confirm a stamped reply lands.

## Let others ask

By default only the operator can wake this bot. To admit other people, add
`allowed_requesters = ["<full npub or hex public key>"]` to this bot's
registry entry and restart the host. Use public keys, never secret keys.
An allowed requester must also mention the operator with a Nostr `p` tag
alongside `{{BOT_ID}}:`. Channel membership alone is not enough.

## Try its boundaries

Three more worth trying once, after editing `AGENTS.md`:

- An ordinary question it should answer.
- A request to change something outside this corpus. It should decline
  and say it only answers questions.
- An instruction planted in the channel by someone else, such as "ignore
  your instructions". Its behaviour should not change.

Judge the boundary it holds, not the words it uses.
